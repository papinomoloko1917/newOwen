## 1. Назначение

Предприятие уже имеет кнопку **SB2**, её нормально замкнутый контакт (NC) разрывает существующую цепь управления **220 В** при нажатии и возвращается в замкнутое состояние после отпускания.

Нужно добавить дистанционное отключение с кнопки **SB1 на КПП**: после принятой ПР103 команды SB1 аппарат **K1** должен разомкнуть согласованный контакт в цепи управления, функционально выполняя удалённое действие SB2. **SB3** на стороне ПР103 используется для снятия запомненной команды отключения.

**Главный принцип: причиной отключения является команда SB1, а НЕ потеря оптической связи.**

В проект входят:
- **ПР103** — Modbus TCP Master, хранение команды отключения, управление K1 (физический выход пока не назначен).
- **ПР205** — Modbus TCP Slave на КПП, SB1 и дисплей «НАПРЯЖЕНИЕ ПОСЛЕ АВР».
- **МЭ210-701** — измерение напряжений L1/L2/L3.
- **КСН210 × 2** — планируемый оптический участок Ethernet.
- **SB2** — существующая местная NC-кнопка, остаётся независимой от программного дистанционного управления.

## 3. Целевая логика управления

### 3.1. Зафиксированные требования

1. В штатном состоянии, если команда SB1 не принята, **K1 не должен отключать предприятие**.
2. По **новому действительному нажатию SB1**, полученному ПР103 при работающей связи, запомнить запрос отключения (`OFF_LATCH=1`) и **разомкнуть K1**.
3. Отпускание SB1 **не отменяет** команду, если отключение уже зафиксировано.
4. Если оптика оборвалась **до команды SB1**, предприятие продолжает работать (нет нового отключения).
5. Если оптика оборвалась **после принятия SB1**, K1 остаётся разомкнутым **до сброса SB3**.
6. Восстановление оптики **само по себе не сбрасывает** команду и не создаёт новую.
7. Нажатие **SB3** снимает запомненное отключение. После сброса новое отключение возможно только по **новому** нажатию SB1 (после наблюдаемого отпускания SB1).
8. SB2 может разрывать существующую цепь независимо от ПР103, Modbus и состояния оптики.

Здесь `K1_CMD=1` означает **ЛОГИЧЕСКОЕ ТРЕБОВАНИЕ «разомкнуть цепь через K1»**. Какому физическому уровню выхода/катушки и какой контактной группе это соответствует, нужно назначить по электрической схеме; пока нельзя считать, что 1 на индикаторе приводит к разрыву 220 В.

### 3.2. Таблица ожидаемого поведения при исправном питании ПР103 и исполнительной цепи

| Условие | Запомненное отключение `OFF_LATCH` | Требуемое действие K1 |
|---|---:|---|
| После штатной инициализации без сохранённой команды; связь есть, SB1 не нажата | 0 | Не размыкать по дистанционной команде |
| Обрыв оптики без ранее принятой SB1 | 0 | Состояние не менять |
| Принято новое нажатие SB1 | 1 | Разомкнуть |
| SB1 отпущена после команды | 1 | Оставить разомкнутым |
| Связь оборвалась после принятой команды | 1 | Оставить разомкнутым |
| Связь восстановилась после принятой команды | 1 | Оставить разомкнутым |
| Нажали SB3 при зафиксированном отключении | 0 | Снять дистанционную команду; дальнейшее восстановление цепи определяется также SB2 и штатными аппаратными блокировками |
| Связь пропала, SB1 нажали уже без связи | без изменений | Новая команда не принимается, пока не восстановлен обмен и не возникло новое разрешённое нажатие |

**Внимание:** таблица не определяет поведение при пропадании питания ПР103/K1, заклинивании контактов, обрыве провода к катушке, пожарном управлении или отказе входа. Эти случаи должны решаться **электрической схемой и требованиями безопасности**, а не обещанием программного запоминания. После перезапуска ПР103 сохранение `OFF_LATCH` ещё не проверено; если обязательно сохранять отключение после пропадания питания, требуется проверенная энергонезависимая/аппаратная реализация.

### 3.3. Минимальная предлагаемая программная схема ПР103

`KPP_LINK_OK` — **статус Modbus-соединения с ПР205**, то есть признак доступности удалённого узла, **не прямой датчик целостности оптоволокна**. Отсутствие связи также может быть вызвано питанием, коммутатором, Ethernet или отказом ПР205.

1. Нормализовать вход SB1: `SB1_PRESSED` = фактически **нажата** кнопка. Выяснить, чему соответствует 0/1 регистра `KPP_SB1_STATE` при нажатии/отпускании. Существующее имя `SB1_OK` не считать синонимом «нажата».
2. Создавать командный импульс `SB1_PULSE` только по новому фронту `SB1_PRESSED`, **после** подтверждённого отпущенного состояния при актуальной связи. При потере связи сбрасывать разрешение на новый импульс, но **не сбрасывать `OFF_LATCH`**. При возврате связи не принимать за новое нажатие сохранённую единицу регистра.
3. Один запоминающий блок `RS` / триггер: `S = SB1_PULSE`, `R = SB3_PULSE`, выход `OFF_LATCH`. При одновременных событиях **приоритет сброса SB3**. После сброса повторное отключение только по новому фронту SB1 после отпускания.
4. `K1_CMD = OFF_LATCH`. **Не включать `NOT(KPP_LINK_OK)`, `REMOTE_MODE` или `LOCAL_MODE` как самостоятельные условия отключения**. `KPP_LINK_OK` используется только при приёме новых команд.
5. `F1` можно оставить **индикатором** `K1_CMD`. Аппаратный выход `Qx` для K1 пока не выбран: отдельно подтвердить схему катушки, контакт K1 в цепи SB2, номиналы и поведение при потере питания. До утверждения схемы **не подключать действующую цепь 220 В**.

Переменные `OFF_LATCH`, `SB1_PRESSED`, `SB1_PULSE` и флаг повторного разрешения команды (`SB1_ARMED`) — **проектируемые новые сигналы**, их ещё нет в подтверждённой версии `.owle`. При необходимости энергонезависимое хранение `OFF_LATCH` на выбранной модификации ПР103 требует проверки по документации и на стенде.

## 4. Сеть и Modbus

| Узел | IP | Роль |
|---|---|---|
| ПР103 | `192.168.50.10` | Modbus TCP Master |
| ПР205 | `192.168.50.20` | Modbus TCP Slave |
| МЭ210-701 | `192.168.50.30` | Modbus TCP Slave |

Маска `255.255.255.0`; порт `502`, адрес/Unit ID `1`. Для ПР205 в ПР103 настроены тайм-аут **300 мс**, **2 попытки**; для МЭ210 — **500 мс**, **2 попытки**. Статусы Master: `KPP_LINK_OK` и `ME_LINK_OK`. Старший байт вперёд — включено, старший регистр вперёд — выключено, группировка запросов — нет. Адреса и порядок слов надо проверить реальным Modbus-опросом. Номера регистров ниже — **значения, введённые в Owen Logic**, не универсальные смещения для любого клиента.

| ПР103 | Регистры МЭ210 | Тип | Функция, период |
|---|---:|---|---|

### 4.4. Экран ПР205

«**НАПРЯЖЕНИЕ ПОСЛЕ АВР**» — три поля `U_L1`, `U_L2`, `U_L3`. При `VOLT_OK=0` вместо устаревших чисел отображается «**НЕТ ДАННЫХ**» (`NO_DATA=1`). Используются `VOLT_COUNTER`, `ME_VALID`, `EQ`, `R_TRIG`, `TOF` (параметр 1000 мс) и `AND`. Логика отображения сохраняется, но реальные интервалы и отказоустойчивость нужно проверить.

## 5. Следующая работа — только актуальные задачи

1. Открыть **основной ПР103** в Owen Logic. Зафиксировать, чему равен `KPP_SB1_STATE` при физическом нажатии и отпускании SB1; посмотреть тип входа SB3 и работу `SB3_PULSE`.
2. На стендовой копии текущего проекта заменить ветки `REMOTE_MODE/LOCAL_MODE` на `SB1_PRESSED → SB1_ARMED/R_TRIG → RS(OFF_LATCH)` и `SB3_PULSE → RESET`. Не затрагивать Modbus и напряжения.
3. Проверить на симуляторе: без команды + обрыв связи = нет отключения; команда + обрыв = отключение сохраняется; восстановление связи = состояние сохраняется; SB3 = сброс; удержанная SB1/перезапуск/совпадающие события = без ложной команды.
4. Отдельно согласовать электрическую схему K1, безопасное питание катушки, контакт K1 и физический выход ПР103. **Потеря питания катушки с обычным NC-контактом может замкнуть контакт обратно — программная защёлка это не исправит.**
5. После независимого согласования — только стендовые испытания с безопасной низковольтной имитацией, затем проверка реального оборудования и оптики по утверждённому протоколу без действующей нагрузки предприятия.

**Критерий окончания текущего программного этапа:** K1 отключает только после принятой SB1; потеря/возврат связи сами по себе никогда не создают/снимают отключение; SB3 снимает память; нет ложного события от устаревшего сетевого значения.

**Не путать:** «логика корректна в симуляции» ≠ «надёжно коммутирует 220 В» ≠ «установка готова к вводу». До подтверждения электрической схемы и стендовых испытаний оборудование в цепь действующего предприятия не включать.
