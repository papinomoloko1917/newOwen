# newOwen — ПР103, ПР205, МЭ210-701 и управление K1

> **Статус на 16.11.2026:** программная логика разрабатывалась и проверялась в симуляторе Owen Logic. **Реальные испытания оборудования, Ethernet/Modbus TCP и оптоволоконной линии ещё не проведены.** Данный README — описание текущей конфигурации и план приёмочных проверок, а не подтверждение готовности к эксплуатации.

## 1. Назначение

Проект объединяет:
- **ПР103** — основной контроллер логики, обмена Modbus TCP, выбора дистанционного/местного режима и формирования команды `K1_CMD`.
- **ПР205** — контроллер на КПП с кнопкой `SB1`, экраном напряжений трёх фаз и индикацией отсутствия данных.
- **МЭ210-701** — источник измерений напряжений фаз L1/L2/L3 по Modbus TCP.
- **Два КСН210** — предполагаемый оптоволоконный участок связи (физическая конфигурация и испытания пока впереди).
- **K1** — исполнительный аппарат, команда на который вычисляется в ПР103. **Критически важно: `F1` в схеме — пользовательский светодиод ПР103, НЕ релейный выход. Физическое управление K1 в текущем проекте НЕ реализовано. До монтажа нужно выбрать и подключить выход `Q1…Q10` (DO), согласовать нагрузку, защиту и аппаратные блокировки.**

Функции: передавать измеренные напряжения на экран ПР205, скрывать неактуальные показания, контролировать доступность сетевых устройств, переключаться между режимами и формировать логическую команду на K1.

### Упрощённая структура

```text
                  Ethernet / Modbus TCP
МЭ210-701 (.30) ────────────┐
                            v
                       ПР103 (.10)
                            |  чтение SB1 / запись U_L1..3,
                            |  ME_VALID, VOLT_COUNTER
                            v
                       ПР205 (.20) ── экран «Напряжение»
                            |
                            └── SB1 (состояние доступно ПР103)

ПР103: SB3 → логика REMOTE_MODE / LOCAL_MODE
     → K1_CMD → F1 (ТОЛЬКО пользовательский светодиод; нет физического управления K1)

КСН210 ↔ оптический участок ↔ КСН210:
физическое включение и отказоустойчивость не подтверждены.
```

IP-адреса в скобках — последние октеты сети `192.168.50.0/24`.

## 3. Сетевые настройки и адреса

| Устройство | IP в принятой схеме | Маска | Роль |
|---|---|---|---|
| ПР103 | `192.168.50.10` | `255.255.255.0` | Modbus TCP Master |
| ПР205 | `192.168.50.20` | `255.255.255.0` | Modbus TCP Slave |
| МЭ210-701 | `192.168.50.30` | `255.255.255.0` | Modbus TCP Slave |

Принята **статическая адресация**, порт **502**, Modbus Unit ID / адрес **1** для настроенных Master-устройств. Шлюз не требуется для взаимодействия в одной подсети; для выхода за её пределы параметры необходимо согласовать отдельно. IP-адреса ПР103 и ПР205 и настройки самого МЭ210 нужно сверить по реальным приборам до подключения.

В конфигурации **ПР103 → ПР205** основного файла:
- интерфейс Ethernet, протокол TCP/IP, IP `192.168.50.20`, порт 502, адрес 1;
- тайм-аут ответа **300 мс**, попыток **2**;
- старший байт вперёд: **да**; старший регистр вперёд: **нет**;
- группировка запросов: **нет**;
- статус соединения записывается в `KPP_LINK_OK`.

В конфигурации **ПР103 → МЭ210**:
- интерфейс Ethernet, протокол TCP/IP, IP `192.168.50.30`, порт 502, адрес 1;
- тайм-аут ответа **500 мс**, попыток **2**;
- старший байт вперёд: **да**; старший регистр вперёд: **нет**;
- группировка запросов: **нет**;
- статус соединения записывается в `ME_LINK_OK`.

**Внимание к адресации:** номера регистров далее приведены **так, как введены в Owen Logic**. У сторонних Modbus-клиентов может отличаться правило нулевой/единичной адресации и показ 4xxxx. Это необходимо проверить тестовым чтением, а не переносить адреса вслепую.

## 4. Полный перечень именованных переменных ПР103

Перечень сверён с основным `.owle` (внутренние переменные и сетевые модели). `BOOL` — булево значение 0/1; `INT` — целочисленная переменная; `FLOAT32` — 32-битное число с плавающей запятой. Сетевые переменные являются объектами конфигурации Modbus; физические I/O указаны отдельно.

### 4.1. Внутренние переменные ПР103

| Имя | Тип | Назначение |
|---|---|---|
| `KPP_LINK_OK` | BOOL | Статус доступности ПР205 по настроенному Modbus TCP Master |
| `ME_LINK_OK` | BOOL | Статус доступности МЭ210 по настроенному Modbus TCP Master |
| `SB1_OK` | BOOL | Результат сравнения `KPP_SB1_STATE == 1`; разрешающее состояние SB1 |
| `SB3_PULSE` | BOOL | Событие/импульс нажатия SB3, используемый логикой переключения |
| `SB3_ARMED` | BOOL | Переменная объявлена в основной модели ПР103; назначение и фактическое использование в текущей схеме необходимо уточнить (не считать реализованной отдельной защитой) |
| `REMOTE_MODE` | BOOL | Запомненный дистанционный режим (логика RS1) |
| `LOCAL_MODE` | BOOL | Запомненный местный режим (логика RS2) |
| `K1_CMD` | BOOL | Итоговая разрешённая логическая команда на исполнительный аппарат K1; подаётся на F1 |

### 4.2. Сетевые переменные ПР103 ↔ ПР205

На ПР103 используется префикс `KPP_` для сетевых переменных, соответствующих регистрам ПР205.

| Переменная ПР103 | Направление ПР103 | Регистр ПР205 | Функция Modbus | Период | Тип/смысл |
|---|---|---:|---|---:|---|
| `KPP_SB1_STATE` | Чтение из ПР205 | 16384 | `0x03` | 500 мс | INT, состояние SB1 |
| `KPP_VOLT_COUNTER` | Запись в ПР205 | 16385 | `0x10` | 1000 мс | INT, периодический маркер обновления/heartbeat |
| `KPP_U_L1` | Запись в ПР205 | 16386–16387 | `0x10` | 1000 мс | FLOAT32, напряжение L1, В |
| `KPP_U_L2` | Запись в ПР205 | 16388–16389 | `0x10` | 1000 мс | FLOAT32, напряжение L2, В |
| `KPP_U_L3` | Запись в ПР205 | 16390–16391 | `0x10` | 1000 мс | FLOAT32, напряжение L3, В |
| `KPP_ME_VALID` | Запись в ПР205 | 16392 | `0x10` | 1000 мс | INT 0/1, признак доступности данных МЭ210 |

Запись `0x10` — **Write Multiple Registers**, чтение `0x03` — **Read Holding Registers**. Для FLOAT32 используются два 16-битных регистра. На стороне ПР205 функции 0x10 не требуется создавать как отдельные Master-опросы: ПР205 предоставляет регистры как Slave, а ПР103 в них записывает.

### 4.3. Сетевые переменные ПР103 ← МЭ210-701

| Имя ПР103 | Регистр МЭ210 | Функция | Период | Тип/смысл |
|---|---:|---|---:|---|
| `ME_U_L1` | 5240–5241 | `0x03` | 1000 мс | FLOAT32, измеренное напряжение L1 |
| `ME_U_L2` | 5242–5243 | `0x03` | 1000 мс | FLOAT32, измеренное напряжение L2 |
| `ME_U_L3` | 5244–5245 | `0x03` | 1000 мс | FLOAT32, измеренное напряжение L3 |

ПР103 получает три величины, переносит их в `KPP_U_L1/L2/L3`, а признак `ME_LINK_OK` используется при формировании `KPP_ME_VALID`.

### 4.4. Физические входы и выходы ПР103

- `I1` — вход, участвующий в логике SB3. В тестовом проекте на его месте для проверки также использовалась константа 0/1; **назначение реальной клеммы, тип контакта и схема подключения SB3 подлежат сверке**.
- `F1` — **программируемый пользовательский СВЕТОДИОД** ПР103, а не физический силовой/релейный выход. В текущей схеме `K1_CMD` управляет только этим индикатором. Для реального контактора необходимо подключить `K1_CMD` к выбранному физическому дискретному выходу `Q1…Q10` (DO), проверив тип выходного каскада, ток катушки, цепи подавления перенапряжения и аппаратные блокировки.
- Прочие видимые `I*`, `Q*`, `FI*`, `AI*`, `AO*` на полотне — аппаратные каналы модели, а не дополнительные именованные программные переменные. Не считать их подключёнными к оборудованию без электрической схемы.

## 5. Полный перечень переменных ПР205

### 5.1. Сетевые переменные Modbus Slave

| Имя ПР205 | Регистр | Тип | Источник/назначение |
|---|---:|---|---|
| `SB1_STATE` | 16384 | INT | Состояние кнопки SB1 на ПР205; считывается ПР103 |
| `VOLT_COUNTER` | 16385 | INT | Маркер обновления/heartbeat, записывается ПР103 |
| `U_L1` | 16386–16387 | FLOAT32 | Напряжение фазы L1, записывается ПР103 |
| `U_L2` | 16388–16389 | FLOAT32 | Напряжение фазы L2, записывается ПР103 |
| `U_L3` | 16390–16391 | FLOAT32 | Напряжение фазы L3, записывается ПР103 |
| `ME_VALID` | 16392 | INT | Достоверность/доступность МЭ210 (0/1), записывается ПР103 |

### 5.2. Внутренние переменные ПР205

| Имя | Тип | Назначение |
|---|---|---|
| `VOLT_OK` | BOOL | Разрешение показа напряжений при признаке данных и обнаружении обновлений; в схеме используются `EQ`, `R_TRIG`, `TOF`, `AND` |
| `NO_DATA` | BOOL | `NOT(VOLT_OK)`; включает сообщение «НЕТ ДАННЫХ» |

В этой схеме `SB1_STATE` формируется через `SEL` (значения 0/1), `VOLT_COUNTER` контролируется сравнением с 1 и фронтом `R_TRIG`, а `ME_VALID` сравнивается с 1. Использован `TOF` с параметром **1000 мс**. Фактическое время срабатывания индикации при нарушениях связи ещё требует отдельного замера на стенде.

### 5.3. Экран «Напряжение»

Экран ПР205 показывает заголовок **«НАПРЯЖЕНИЕ ПОСЛЕ АВР»** и три числовых поля L1/L2/L3 с привязкой к `U_L1/U_L2/U_L3`. При `VOLT_OK=0` показания скрываются, а `NO_DATA=1` выводит **«НЕТ ДАННЫХ»**.

В симуляторе отображались `00230.1`, `00228.7`, `00231.4` В. Ведущие нули — лишь форматирование полей, не ошибка измерений. Эти значения **были заданы в симуляции**, а не прочитаны с реального МЭ210.

## 6. Логика режимов и команда K1 (ПР103)

На основном полотне Owen Logic реализованы блоки `R_TRIG`, `RS`, `AND`, `OR`, `NOT`, `EQ`, `SEL`. Принцип работы текущей схемы:

1. ПР103 получает статус сети ПР205 (`KPP_LINK_OK`) и состояние кнопки SB1 (`KPP_SB1_STATE`).
2. `EQ(KPP_SB1_STATE, 1)` создаёт `SB1_OK`.
3. Ветка SB3 формирует `SB3_PULSE` и управляет запоминающими блоками режимов `REMOTE_MODE` / `LOCAL_MODE`; изменение состояния и связь участвуют в разрешающих условиях.
4. Команда `K1_CMD` формируется логическими комбинациями активного режима, наличия связи и `SB1_OK`; на полотне предусмотрена местная ветка при отсутствии сетевой связи.
5. `K1_CMD` соединена с `F1`, **который является пользовательским светодиодом ПР103**; физическое включение K1 пока не реализовано. Требуется отдельная связь на аппаратный выход `Q1…Q10` после инженерной проверки.

**Важно:** точная политика приоритетов при одновременных событиях, поведение при перезапуске, антидребезг, реакция на залипший вход и физические блокировки K1 пока не подтверждены. Включение контактора **не может зависеть только от успешной симуляции**: необходимо предусмотреть электрическую защиту, блокировки, безопасное состояние при отказе и проверку схемы ответственным специалистом.

## 7. Что выполнено

Ход работы по проекту:

1. Созданы проекты Owen Logic для ПР205 и ПР103, настроен сетевой Modbus Slave на ПР205.
2. На ПР205 созданы регистры `SB1_STATE`, `VOLT_COUNTER`, `U_L1`, `U_L2`, `U_L3`, `ME_VALID`.
3. На ПР103 добавлены два Modbus TCP Master-устройства: **ПР205** и **ME210_AVR**, настроены IP-адреса, тайм-ауты, функции чтения/записи и регистры.
4. Выполнена схема передачи напряжений МЭ210 → ПР103 → ПР205.
5. Построена логика дистанционного и местного режима с SB1/SB3, `REMOTE_MODE`, `LOCAL_MODE`, `K1_CMD`; выполнено соединение `K1_CMD → F1`.
6. В симуляторе ПР103 последовательно проверялись комбинации `KPP_LINK_OK`, `KPP_SB1_STATE` и импульса SB3; наблюдались переключения **светодиодного индикатора** `F1` 0/1 (это не подтверждает работу реального выходного контакта K1). Проводились также тесты, обозначенные в рабочем журнале как проверки до №9. **Формальный протокол со всеми входными комбинациями ещё не оформлен.**
7. На ПР103 реализованы `KPP_ME_VALID` и `KPP_VOLT_COUNTER`; на ПР205 реализованы `VOLT_OK` и `NO_DATA`.
8. Исправлены настройки видимости элементов дисплея. В симуляции подтверждены два состояния:
   - `ME_VALID=0` или отсутствие разрешения `VOLT_OK`: экран сообщает **«НЕТ ДАННЫХ»**;
   - `ME_VALID=1` и `VOLT_OK=1`: выводятся три фазы, в тесте **230.1 / 228.7 / 231.4 В**.
9. Проверено восстановление отображения после тестовой потери данных. Рабочие проекты сохранены в репозиторий.

**Подтверждено только моделирование логики**. Симулятор Owen Logic не подтверждает реальные тайминги Modbus TCP, достоверность измерений, физический отказ кабеля, запуск/перезапуск и безопасную коммутацию K1.

- **F1 у ПР103 — пользовательский светодиод, НЕ релейный выход.** Поэтому даже при успешной симуляции `K1_CMD → F1` физический контактор не будет включаться. Для исполнительной цепи нужно выбрать `Q1…Q10` и проработать её защиту. Источник: [официальное руководство ПР103](https://docs.owen.ru/product/pr103/897).

Проверить поддерживаемый стандарт, длину линии, тип волокна, разъёмы и оптический бюджет. ## 8. План испытаний на оборудовании

До начала: сохранить копии `.owle`, проверить реальные модификации устройств и прошивки, отдельное питание/заземление, монтаж Ethernet и КСН210, схему аппаратных блокировок. **Не подключать реальную нагрузку K1 до подтверждения безопасного исполнения цепи управления.**

| № | Испытание | Действие | Ожидаемый результат |
|---|---|---|---|
| 1 | Проверка конфигураций | Сравнить прошивки/модели, IP, маски, адреса Modbus, порядок слов/байтов и загрузить утверждённые проекты | Нет конфликтов IP и ошибок конфигурации |
| 2 | Связь ПР103—ПР205 | Проверить доступность `192.168.50.20:502`, чтение `SB1_STATE` и запись тестовых регистров | `KPP_LINK_OK=1`; SB1 читается корректно |
| 3 | Связь ПР103—МЭ210 | Проверить `192.168.50.30:502`; считать 5240/5242/5244 и сравнить с показаниями прибора | `ME_LINK_OK=1`, числа правдоподобны, порядок регистров верен |
| 4 | Сквозная передача | Проверить `ME_U_L1/L2/L3` → `KPP_U_L1/L2/L3` → `U_L1/L2/L3` → экран | Все три фазы совпадают с эталоном в заданной погрешности |

| 6 | Возврат МЭ210 | Восстановить канал и дождаться нескольких циклов опроса | Показания появляются автоматически, без устаревших чисел |

### Уточнение назначения K1

**Требование пользователя/заказчика:** установленная кнопка **SB2 — NC (нормально замкнутая)**; при нажатии **разрывает цепь 220 В**, при отпускании **снова замыкает**. K1 должна обеспечить **удалённое функциональное повторение SB2** в согласованной цепи управления (последовательность включения, контактная группа и полярность должны быть подтверждены по электросхеме). Не следует без проверки считать, что длительная логическая команда `K1_CMD=1` означает постоянный физический разрыв: это зависит от реального реле и использования NO/NC контакта.

**Уточнение статуса:** режимы `REMOTE_MODE`/`LOCAL_MODE` и команда `K1_CMD` — результаты программной логики; они сами по себе не подтверждают кратковременное нажатие эквивалента SB2 или его безопасное восстановление. По скриншотам после отпускания SB3 могут сохраняться `REMOTE_MODE=1`, `K1_CMD=1` и `F1=1`. Это подтверждает фиксацию *логического состояния*, но не физическое действие K1. `F1` остаётся **пользовательским светодиодом**, не силовым выходом.
