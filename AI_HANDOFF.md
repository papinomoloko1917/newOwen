# AI_HANDOFF — текущая контрольная точка 19.11.2026

**Источник истины:** [README.md](README.md), начало документа «Актуальная контрольная точка — 19.11.2026». В репозитории работать с двумя существующими OWLE, без множества копий: [ПР103](ПР103-24.1610.03.1.0.owle) и [ПР205](ПР205-24.1211.02.0.0.owle). **Статус: разработка / SIM_ONLY / не допущено к эксплуатации.** Последние скриншоты Owen Logic могут отражать локальные изменения, отсутствующие в GitHub; не объявлять совпадение без проверки файлов.

## Последнее принятое решение

- **SB1** — предполагаемая фиксируемая поворотно-освобождаемая IEK MASTER MI-BG60-11ZS-3-23-K04 (1NO+1NC). Достоверное нажатие при исправной связи создаёт дистанционный запрет; достоверное отпускание при исправной связи снимает его **без SB3**.
- **SB3** — местный резервный сброс *только* при потере связи **после** уже принятого отключения. После сброса старая «нажатая» SB1 не должна повторно формировать команду. Требуется достоверная новая последовательность «отжата → нажата».
- Потеря связи сама по себе не меняет принятое состояние команды. **`KPP_LINK_OK` не гарантирует свежесть `KPP_SB1_STATE`**, особенно при восстановлении Modbus.
- **Отказ от усложнения:** экспериментальный «кадр» `SB1_FRAME` / `KPP_SB1_FRAME` (самодельная упаковка `2 × счётчик + состояние SB1`) и цепь `BLINK/CTN/MUL/ADD/DIV/EXTRACT/EQ/NOT/TOF` предлагается удалить из основного пути управления. **Пока по последним скриншотам блоки существуют; это ещё не выполненное удаление.** Упрощение не решает автоматически проблемы старого регистра, повторного запуска и потери питания.
- Не путать **снятие дистанционного запрета** с разрешением на автоматический запуск предприятия; если SB1 используется для настоящего аварийного останова, такая схема через обычный Modbus TCP/с возможностью обхода SB3 не является допустимой заменой независимой системы безопасности.

## По последним скриншотам Owen Logic 19.11.2026

**ПР205:** `I1 → SEL → SB1_STATE`; экспериментальная ветка формирует `SB1_FRAME`, опубликованную локально как сетевой INT. В симуляции менялись параметры циклов и наблюдался сброс значений; сквозного Ethernet-теста нет.

**ПР103:** локально изображены `SB1_PRESSED`, `SB1_ARMED` (RS4), `OFF_LATCH` (RS5), `SB1_RX_PRESSED`, `SB1_RX_OK`, `KPP_SB1_FRAME` и арифметический декодер. Старая схема `REMOTE_MODE/LOCAL_MODE` продолжает встречаться в управляющей ветке `K1_CMD`. **Нет подтверждения полной функциональной замены, прошивки, физического реле K1 или приёмки.** `F1/F2` — индикаторы, `Q1` — физический выход FBD; электрическое соединение с K1 не проверено.

**Адреса по настройкам:** ПР103 Master `192.168.50.10`; ПР205 Slave `192.168.50.20`; МЭ210-701 Slave `192.168.50.30`; порт 502. Нормальная SB1 — регистр 16384 (FC03/500 мс); экспериментальная `SB1_FRAME` — 16393 (FC03/500 мс). Регистры измерений и служебных данных 16385–16392, напряжения МЭ210 5240–5245 — сохранять. Вся конкретная фактическая конфигурация и обмен требуют проверки на актуально сохранённых OWLE и стенде.

1. Сверить **два существующих** локальных OWLE с GitHub; не создавать дубли и не восстанавливать устаревшие экспериментальные проекты. История Git служит для отката.
2. Согласовать физический тип NO/NC SB1, полярность `SB1_PRESSED`, топологию Q1–K1–SB2 и принцип безопасного повторного включения. Красный «грибок» сам по себе не доказывает соответствие требованиям аварийного останова.
3. В действующих проектах удалить экспериментальную цепь кадра из основного управления **только после** проверки её зависимостей и заменить на минимальную проверяемую схему. `SB1_ARMED` и `OFF_LATCH` должны учитывать потерю связи, допустимый SB3, старые значения, новое подтверждённое нажатие и перезапуск.
4. Проверить все ключевые последовательности в SIM: SB1 0→1→0 при здоровой связи; потеря связи до/после отключения; SB3 при обрыве; возврат с SB1=1 после SB3; новое отжатие/нажатие; рестарты; зависшие/повторённые значения. **Каждый тест пока OPEN в контексте новой конечной логики**, пока не собрана воспроизводимая запись результатов.
5. Только после полной регрессии переназначать `K1_CMD`; не менять измерения МЭ210, `VOLT_OK/NO_DATA`, экран ПР205 без отдельной причины.
6. Перед любой эксплуатацией — утверждённая электросхема, анализ опасностей и отдельные испытания на изолированном стенде, включая отказ питания, контакты, предотвращение самозапуска, независимую SB2.

# AI_HANDOFF — актуальный checkpoint newOwen

**Дата:** 18.11.2026. **Рабочая ветка:** `main`.  
**Источник истины:** [README.md](README.md) этого же коммита или более нового. **Не возвращаться** к постановке от 17.11.2026 (SB1 — кратковременный импульс, SB3 — обычный сброс). Действующие исходники: только [ПР103](ПР103-24.1610.03.1.0.owle) и [ПР205](ПР205-24.1211.02.0.0.owle). Устаревшие тесты и autosave не использовать.

## 1. Что изменено и почему

**Новый принцип управления, подтверждённый пользователем:**

- **SB1 на КПП** — красная механически фиксируемая кнопка «Грибок» IEK MASTER **MI-BG60-11ZS-3-23-K04**, 1NO+1NC, разблокировка поворотом. Это **предлагаемая модель**, пока не установлена. Предыдущую нефиксируемую IEK LAY5-BA31 в качестве SB1 больше **не** предлагать.
- При исправной связи ПР103–ПР205: **зафиксировали SB1 → приняли дистанционное отключение K1**; **повернули/отжали SB1 → достоверно приняли отпускание → сняли дистанционную команду без SB3**.
- Если связь пропала **до** принятой команды: **не отключать** только из-за отсутствия связи.
- Если связь пропала **после** принятой SB1: **сохранить** логическое отключение K1 даже при недоступности ПР205.
- **SB3 возле ПР103** — только **исключительный местный сброс** уже принятой команды при потере связи с ПР205, а **не** основной способ восстановления при здоровой связи. После SB3 старое удержанное значение SB1 не должно снова автоматически отключать; нужна новая подтверждённая последовательность «отжата → нажата» при свежем обмене.
- При восстановлении связи с **зафиксированной** SB1 ранее принятое отключение сохраняется (если не было местного сброса), при восстановлении связи с **подтверждённо отпущенной** SB1 прежнее отключение можно снять. Одно только изменение флага `KPP_LINK_OK` команду не создаёт и не снимает.
- **SB2** — существующая независимая NC-кнопка местного отключения, её цепь не изменять без утверждённой электрической схемы.
- **Не считать** отпускание красного «грибка» автоматическим разрешением пуска потенциально опасных машин. Дистанционное снятие запрета и физическое восстановление питания/пуск разделять. Квалификация кнопки как emergency stop и соответствие нормам безопасности **не установлены**.

**Критическое отличие:** прежняя логика `OFF_LATCH` «сбрасывается только SB3; отпускание SB1 не действует» **ОТМЕНЕНА**. Точная реализация FBD ещё не утверждена/не испытана.

## 3. Требуемая логика (не отождествлять с уже работающей программой)

| Событие | Логическая команда размыкания K1 |
|---|---|
| Связь исправна, SB1 отжата | 0 |
| Получена свежая команда SB1 зафиксирована | 1 |
| SB1 удерживается зафиксированной | 1 |
| Получено свежее состояние SB1 отжата, связь исправна | 0; SB3 не требуется |
| Связь потеряна до принятой SB1 | Не менять |
| Связь потеряна после принятой SB1 | Сохранять 1 |
| SB1 отжата во время потери связи | Сохранять 1 до нового достоверного чтения или допустимого SB3 |
| Связь вернулась, подтверждена SB1 отжата | Снять прежнюю команду |
| Связь вернулась, SB1 зафиксирована и SB3 не применялась | Сохранять прежнюю команду |
| При потере связи и принятой команде нажали SB3 | Снять команду, заблокировать повторное принятие старой единицы |
| После SB3 связь вернулась, SB1 всё ещё нажата | Не отключать повторно, пока не увидели свежее «отжата → нажата» |
| Связь восстановилась с зафиксированной SB1, которую нажали впервые **во время обрыва** | Не принимать старую единицу как новое нажатие; требовать новый цикл отпускания/нажатия |
| Совпадение событий SB1 и разрешённого SB3 | Приоритет безопасно согласованного местного сброса; проверить симуляцией |

**Неопределено:** гарантированная свежесть `KPP_SB1_STATE` при Modbus TCP, момент смены `KPP_LINK_OK`, свойства 1NO/1NC на реальных клеммах, состояние после питания/перезапуска, поведение K1 при отказах. **Не выдавать модель на бумаге за готовую работающую FBD**.

Предварительные проектируемые сигналы: `SB1_PRESSED` (нормализованное положение), `SB1_ARMED` (только после свежего подтверждения отпускания), `SB1_PULSE` (новый допустимый фронт), `OFF_LATCH` (последняя принятая команда до свежего отпускания или допустимого SB3), `K1_CMD` (логическая команда). `KPP_LINK_OK` сам по себе **не** является доказательством свежего успешного чтения. **Не вводить** `NOT KPP_LINK_OK` как самостоятельную команду K1.
